# 分类逻辑规范

> 这份文档定义了 618 加购面板的正确分类逻辑。
> 数据已用真实 5 月数据验证过 75 个数据点（详见 测试用例.csv）。

## 0. 数据源

每天一个生意参谋导出的 .xls 文件，列结构示例：

| 统计日期 | 商品ID | 商品名称 | ... | 商品加购人数 | ... |
|---|---|---|---|---|---|
| 2025-05-01 | 824452791755 | HAY Facet Cabinet 边柜... | | 8 | |

合并到一张大表后做日聚合。

另有一张「分类底表」(就是 handoff/data/分类映射表.xlsx)，结构：

| 商品ID | 一级 | 二级 |
|---|---|---|
| 679198301351 | 配饰 | 收纳盒 |
| 690221882602 | 家具 | 边几 |

**重要：分类底表里的「一级」字段历史上有数据质量问题——同一个商品 ID 有时候打成「配饰」有时候打成「配件」（二级是一致的）。这两个一级值实际上是同一类，要合并。**

## 1. 分类规则（必须严格按这个顺序）

```
对每条日报数据 (统计日期, 商品ID, 商品名称, 商品加购人数, ...)：

  1. 用 商品ID 去 LEFT JOIN 分类映射表
  2. IF 匹配到了:
       分类 = 映射表的 一级
       IF 分类 = '配件' THEN 分类 = '配饰'   -- 合并
       -- 即使商品名称是 "-" 或包含 "已合并" 也不要排除！
  3. ELSE (没匹配到):
       IF 商品名称 IS NULL OR TRIM(商品名称) IN ('', '-'):
           分类 = '__排除__'
       ELSEIF 商品名称 LIKE '%测试%' 
           OR 商品名称 LIKE '%展【%' 
           OR 商品名称 LIKE '%【积分兑换】%' 
           OR 商品名称 LIKE '%邮费%':
           分类 = '__排除__'
       ELSEIF 商品名称 LIKE '%灯%':
           分类 = '灯具'
       ELSEIF 商品名称 LIKE '%沙发%' 
           OR 商品名称 LIKE '%椅%'
           OR 商品名称 LIKE '%茶几%'
           OR 商品名称 LIKE '%桌%':
           分类 = '家具'
       ELSE:
           分类 = '配饰'
```

## 2. 聚合规则

```
SELECT
  统计日期,
  分类,
  SUM(商品加购人数) AS 加购人数
FROM 分类后的明细表
WHERE 分类 IN ('配饰', '家具', '灯具')   -- 只保留这三类，排除「__排除__」和「购物金」
GROUP BY 统计日期, 分类
```

## 3. SQL 模板（标准 SQL，按你的方言调整）

```sql
WITH 分类映射 AS (
  SELECT
    商品ID,
    -- 取每个 商品ID 出现频次最高的一级（处理一级冲突的情况）
    CASE 
      WHEN MAX(CASE WHEN 一级 = '配件' THEN 1 ELSE 0 END) = 1 
        OR MAX(CASE WHEN 一级 = '配饰' THEN 1 ELSE 0 END) = 1 
      THEN '配饰'   -- 配件和配饰都归到配饰
      ELSE MAX(一级)
    END AS 一级
  FROM 分类底表
  GROUP BY 商品ID
),
分类后 AS (
  SELECT
    d.统计日期,
    d.商品ID,
    d.商品名称,
    d.商品加购人数,
    CASE
      -- 在映射表里就用映射表的（注意：即使名字是 '-' 或带「已合并」也不要排除）
      WHEN m.一级 IS NOT NULL THEN m.一级

      -- 不在映射表里：先看要不要排除
      WHEN d.商品名称 IS NULL OR TRIM(d.商品名称) IN ('', '-') THEN '__排除__'
      WHEN d.商品名称 LIKE '%测试%' THEN '__排除__'
      WHEN d.商品名称 LIKE '%展【%' THEN '__排除__'
      WHEN d.商品名称 LIKE '%【积分兑换】%' THEN '__排除__'
      WHEN d.商品名称 LIKE '%邮费%' THEN '__排除__'

      -- 然后按规则分类
      WHEN d.商品名称 LIKE '%灯%' THEN '灯具'
      WHEN d.商品名称 LIKE '%沙发%' 
           OR d.商品名称 LIKE '%椅%'
           OR d.商品名称 LIKE '%茶几%'
           OR d.商品名称 LIKE '%桌%' THEN '家具'
      ELSE '配饰'
    END AS 分类
  FROM 商品日报明细 d
  LEFT JOIN 分类映射 m ON d.商品ID = m.商品ID
)
SELECT
  统计日期,
  分类,
  SUM(商品加购人数) AS 加购人数
FROM 分类后
WHERE 分类 IN ('配饰', '家具', '灯具')
GROUP BY 统计日期, 分类
ORDER BY 统计日期, 分类;
```

## 4. ⚠️ 常见踩坑（之前面板写错就是这些原因）

### 坑 1：把「配件」和「配饰」当成两类
分类底表里这两个值其实是历史数据质量问题——同一商品 ID 在不同行被打成不同字。
**必须合并为同一类**（统一叫「配饰」）。

### 坑 2：按商品名关键词预先排除，导致漏掉映射表里的商品
错误写法：
```sql
WHERE 商品名称 NOT LIKE '%已合并%' AND 商品名称 NOT LIKE '%测试%' AND 商品名称 != '-'
```
这会**误排除映射表里手工分类过的商品**。比如：
- `商品ID = 761701702608`，名字是 `-`，但映射表里手工标了「配饰」，每天有 1-4 个加购
- `商品ID = 582883515928`，名字是 `【已合并】HAY Colour Crate S`，映射表里标了「配饰」

正确做法：**只对没在映射表里的商品才看名字做排除**。

### 坑 3：把 LIKE '%椅%' 写成 LIKE '%椅子%'
"扶手椅"、"餐椅"、"吧椅" 都不会匹配 "椅子"。**用单字 "椅"**。
同理「桌」覆盖 "桌子/餐桌/边桌/茶桌"。

### 坑 4：商品加购人数字段类型混乱
- 2025 年的 .xls 文件里这列可能是 int
- 2026 年的 .xls 文件里可能是带逗号的字符串（如 "1,234"）
- 处理时统一转成数字，逗号要去掉，"-" 当作 0

如果你的 ETL 已经清洗过了就不用管；如果是直接从 raw 表读，要 `CAST(REPLACE(REPLACE(商品加购人数,',',''),'-','0') AS INTEGER)` 这种处理。

### 坑 5：聚合时漏掉了过滤购物金
映射表里有 2 个商品被标为「购物金」（HAY 购物金充值卡），这些不是实物商品，不应计入加购总数。
WHERE 子句里要 `分类 IN ('配饰','家具','灯具')`，**不要**用 `分类 != '__排除__'`（那会包含购物金）。

## 5. 排除项预期数量（合理性检查）

跑完分类后，5 月这两个月的数据应该满足：
- **总商品数**（去重 商品ID）：约 471 个
- **映射表命中**：约 396 个
- **规则推断**（不在映射表）：约 38 个
- **排除**：约 14 个

如果排除的超过 30 个，说明 spec 没按顺序执行（可能优先按关键词排除了，把映射表里的商品也排除了）。
