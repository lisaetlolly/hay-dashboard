# 给 Claude Code 的提示词

> 直接复制下面这一整段（包括 ```三个反引号包起来的部分），粘贴到 Claude Code 里就行。
> 它会自己看 spec 文件、找代码、改逻辑、跑测试、push。

---

```
帮我修复 BI 平台上的「618 预热蓄水期加购面板」的分类逻辑。当前面板上的"商品加购人数"按类目（配饰/家具/灯具）的拆分数字是错的，原因是分类逻辑写得有问题。

我把正确逻辑、测试用例和上下文都放在了 ./handoff/ 目录里，请按下面流程做：

### 第一步：理解上下文
先读完这几个文件：
1. handoff/spec/分类逻辑规范.md   ← 核心，正确逻辑 + SQL 伪代码 + 我踩过的坑
2. handoff/spec/测试用例.csv      ← 17 天 × 3 类目的已验证正确数字
3. handoff/spec/思维逻辑.md       ← 我推理过程的精简版（看 4-6 节就够）

### 第二步：定位当前代码
我不确定具体技术栈，可能是 SQL（Hive / MySQL / ClickHouse / BigQuery 之一），也可能涉及 dbt / Airflow / Python。请先：
- 用 grep / find 在仓库里搜：「加购」「商品加购人数」「分类底表」「sycm」「生意参谋」「618」「shopping」「cart」
- 找到生成这个面板的 SQL / 模型文件
- 不确定的话先列出候选文件让我确认，不要自己猜哪个改

### 第三步：按 spec 改写
分类逻辑的关键点（详见规范文档）：
- 映射表里的「配件」和「配饰」是同一类，要合并成「配饰」
- 商品在映射表里就用映射表的分类，**不要**因为名字带「已合并」「-」就排除（这是常见错误）
- 不在映射表里的，按标题关键词分类：含"灯"→灯具，含"沙发/椅/茶几/桌"→家具，其余→配饰
- 排除：购物金、空标题且不在映射表里、含"测试/展【/【积分兑换】/邮费"且不在映射表里
- 日聚合时只保留 配饰/家具/灯具 三类，购物金不计入

### 第四步：验证
用 handoff/spec/测试用例.csv 的 17 天 × 4 项数字（配饰、家具、灯具、总计）跑对比：
- 2025年 5/1-5/12 全部 12 天的预期值
- 2026年 5/1-5/5 全部 5 天的预期值
- 全部对得上才算修好。**任何一格对不上都不要 push**，先告诉我哪天哪个类目差了多少。

### 第五步：交付
- 测试全过 → 提交 + push 到当前分支（如果是主分支，新开一个 fix/cart-category-logic 分支再 PR）
- commit message：`fix(618-dashboard): 修正加购面板的商品分类逻辑`
- commit body 简要说明修了什么（配件/配饰合并、不再按关键词错排已映射商品）
- push 完把 commit hash / PR 链接告诉我

### 几个原则
- 改之前先把当前 SQL 给我看一眼，让我确认是不是这个文件
- 如果数据源是 BI 工具的拖拽面板（不是代码），告诉我，我换方案
- 如果发现 spec 和现有代码冲突的地方比较多（比如字段名不一样、有别的过滤条件），停下来问我，不要硬改
```

## 备用：如果 Claude Code 找不到代码 / 数据源不在仓库里

把这段补给它：

```
代码不在仓库里？那可能是：
1. 直接在 BI 工具里写的 SQL 配置（Superset / Metabase / Quick BI / Tableau / DataWorks）
   → 帮我把正确的 SQL 写出来（基于 handoff/spec/分类逻辑规范.md 里的伪代码），保存为 handoff/output/正确加购SQL.sql，我手动复制到 BI 后台替换
2. 数据是上游 ETL 跑出来后落到表里的，面板只是 SELECT
   → 帮我找上游 ETL 脚本（关键词同上）

无论哪种，最终都要给我一份能跑、跑出来对得上 测试用例.csv 的 SQL。
```
