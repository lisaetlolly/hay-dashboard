## 🚨 必须立刻处理（P0）— 5 件

> 不修这 5 件，下一次发版会比这次还痛。

1. **CTR 全面违反"不加权"铁律** — 后端 8 处都在算 `SUM(clicks)/SUM(impressions)`：`server.py:351, 683, 1289, 1770, 3196, 3331, 3367, 3870`。前端 `compute.js:53` 看似算术均值，但它消费的 `RAW.wxst[].ctr` 已是后端加权后的日值。**而且** `docs/数据口径核对清单.md:9-27` 写着"加权 CTR 是行业标准，已修"——这份文档把工程师反方向引导。先改文档，再改 8 处后端代码，再改 `js/config.js:33` 的 tooltip。

2. **用户冒充 — `X-Username` header 即身份** — `server.py:2921-2935` cookie 是明文 username，`js/api.js:17` 直接把 username 当请求头发后端，`get_current_user` 只 SELECT 不校验签名。**任何人改 `X-Username: admin` 就拿到管理员所有权限**。配合下面 CORS `*` 等于公网开放。

3. **`/api/users/{user_id}` PATCH 完全无鉴权** — `server.py:3028-3046` 没挂 `require_permission`，匿名用户可改任何账号的 username / password / role。比 register 更严重，因为 register 至少要新建账号。同样裸奔的：`update_user_preferences` (L2840)、`update_meeting_note` (L2716)、`update_task_template` (L2166)、`task-periods/*` (L2237/2262/2297)、`/api/plan/category` PUT (L4040)、`/api/app-state` POST (L4143)、`/api/page-views/*`。

4. **`/api/refresh-data` 上传零鉴权 + 路径穿越** — `server.py:4168-4234`：未鉴权、未用 `secure_filename`，`os.path.join(dest_dir, f.filename)` 可走 `..`，并且会 spawn `python3 etl_load.py`（300s 超时）。公网爬虫扫一下就能让 ETL 跑满。

5. **618 加购品类映射违反"底表唯一真相源"铁律** — `etl/etl_618_addtocart.py:27-118` 硬编码 476 个 PID 的品类映射（而 memory 明确底表是 **494 PID**）；`CATEGORY_DAILY_FALLBACK` (L161-185)、`STORE_DAILY_ADDTOCART` (L191) 也是死值，注释明说"xls 实读已关停"。结果：底表更新对 dashboard 完全不可见。

## 4. 功能完整性与潜在 Bug（重点：安全）

### 🔴 严重 / 安全
- **密码裸 SHA-256**（`server.py:2898, 2941, 3035`）— 无 salt、无 bcrypt/argon2，彩虹表秒破，同密码 hash 相同。
- **`/api/users/register` 零鉴权**（L2896）— 任何人能 POST 创建 admin（`role` 直接来自 body，无白名单）。
- **`X-Username` 即身份**（见 P0 #2）。配合 `CORS allow_origins=["*"]`（L182-187），跨站可任意调写接口。
- **多处 PATCH 无 `require_permission`**：见 P0 #3 列表。
- **`/admin/*` HTML 路由零鉴权**（L4302, 4362, 4515, 4574）— 注释直说"不带鉴权（依赖 dashboard URL 不公开）"。`/admin/syzt-import-week-2026-04-27` 一个 GET 就**覆盖 fact_syzt_product**；`/admin/syzt-rerun` 能清空当周数据。搜索引擎一爬就触发。
- **`/api/refresh-data`**（见 P0 #4）。
- **`/api/seeding/kol-webhook` 默认无鉴权**（L4790-4796）— 只有当 `SEEDING_WEBHOOK_TOKEN` env 配置才校验，未配则放行。
- **错误栈直接返回**：`/api/raw-data`（L615-624）、`/api/overview/ranking`（L3736-3743）、`/api/products/full`（L4925/4937）、`verify_user`（L2953）泄露 traceback、表名、DSN。
- **SQL f-string 拼接 SET/WHERE 列名**（L1601, 1604, 2179, 2181, 2436, 2545, 2550, 2584, 2588, 2721, 2725, 3038, 3042）— 值是 `%s` 参数化的，列名 `k` 靠 pydantic schema 限定。**目前不可注入**但模式脆弱，未来加 `dict` 参数路径就崩。`/api/products/full`（L4928）已是 `body: dict`。

### 🟡 中等 / 边界
- 权限模型不一致：`update_task` 手写检查，其它走 `require_permission` Dependency——维护时漏一边。
- `_archive_same_named_tasks` 用 `except Exception` 吞异常只 log warning（L2473），用户看不到半失败态。
- `xhs_user` cookie `httponly=False`（L2931）— JS 可读，配合 XSS 直接拿登录态。
- `/api/refresh-data` 没文件大小限制、只判后缀、未校 MIME，可上传 1GB 假 xls。
- `verify_user` 无限速、无失败计数 → 暴力枚举。
- `permissions.js:isTaskOwner` 用 `display_name.split('（')[0]` 做"主名包含"匹配（L20-22）—"刘"会匹配"刘洋/刘磊"。
- 没有 HTTPS 强制 / HSTS / CSP 头。
- `uvicorn ... reload=True` 在 prod `__main__`（L4992）— reload 模式上线性能差。

### 🟢 技术债 / 死代码
- `etl/etl_load.py.bak`、`_archive/dashboard.html.bak`、`_check_final.py`、`_archive/dedupe_backup_*` —— git 移除。
- L1140-1170 "618 hardcoded merge DB overrides" —— 与铁律 #3 相违。
- L4416-4437 `SPU_MAP` / `BAD_SPU_MAP_REVERT` 在 admin HTML route 里又写一遍。
- 多处 `except Exception: logging.warning(...)` 静默吞异常（L175, 1438, 1497, 1501, 2474, 4120）。
